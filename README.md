# Toolbox

A node workspace for companies that build things one at a time.

> We are not a software company, but we do ship code.
> We are not an AI company, but we do use AI.
> We think you should too.

Every build is one record, from the first quote to the day it leaves the
workshop. Every piece of work done on it is a tool: a node on that record,
holding what it produced and who ran it. The tools are built for you.

---

## The problem

In a bespoke manufacturer, the work that wins an order and the work that
fulfils it live in different systems. The CRM does not know what a bill of
materials is. The ERP does not know a customer was ever spoken to.

Everything between them — the configuration, the quote, the renders, the
promises made — lives in spreadsheets and inboxes. The order reaches the
factory as a name and a date, and the reasoning behind it is gone.

Toolbox is the record that spans the gap, and the tools that hang from it.

## How it works

```
        ┌──────────────── ONE RECORD ────────────────┐
        │   quote ──────── build ──────── delivery   │
        └──────┬───────────────┬──────────────┬──────┘
           CREATE          ANALYSE         OPERATE
```

Sales, production and marketing open the same build. Each sees the tools
their job allows, and nothing else.

## The tools

| Create | Analyse | Operate |
|---|---|---|
| Configure & quote | Audit a build | Job cards |
| Specification documents | Ask the ERP a question | Pick lists |
| Final quotes | Lead research | Parts lists |
| Email teasers, QR cards | Parts, labour and job reports | Handover |
| Listing sheets | Marketing report | Commercial invoice |

Each tool takes one thing and makes another: a build into a configuration, a
configuration into a document, a customer into a briefing. A tool that does
not fit the open record is not offered.

## Built for you

```
submit ──▶ assess ──▶ build ──▶ deploy ──▶ deliverables
```

1. **Submit.** Tell us the work you want done, and what it should produce.
2. **Assess.** We define the tool: what it takes, what it makes, one or many,
   who sees it.
3. **Build.** We build it against your systems and your documents.
4. **Deploy.** It appears as a node in your workspace. Nothing else moves.
5. **Deliver.** Your team runs it, and the output is kept on the record.

Adding a tool is adding a declaration and its screen. The workspace, the
navigation and the permissions around it are untouched.

We are not a software company, but we do ship code: every tool is software
written for one workshop's work, and it ships when that work needs it.

## Where AI is used

Where it earns its place, and nowhere else.

- **Configure with AI** — a car described in words, turned into a priced
  configuration.
- **Lead research** — a briefing on a person before the first call.
- **Ask** — questions about the ERP, answered from the live records.
- **Audit** — a build checked against its own history.

Everything a model produces is kept, with who asked and when.

## Sits on what you have

at handover.
